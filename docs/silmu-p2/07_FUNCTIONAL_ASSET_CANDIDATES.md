## 1. 트랙 A — 신규 제작이 아니라 "이미 있는 도구를 찾게 하기"

05 §4.3 의 실측: **상위 20 중 8건이 "도구는 있는데 질의에 안 잡힌다".**

| 질의 | 답을 가진 기존 도구 | 왜 안 잡혔나 |
|---|---|---|
| "수의계약 한도" | 계약방식 결정 도우미 (`contract_method`) | title/desc/keywords 어디에도 **"한도"** 가 없다 |
| "분할발주" | 분할계약 판단 체크리스트 (`split_contract_checker`) | desc 는 "계약 분할" — **"분할발주"·"분리발주"** 없음 |
| "수입인지"·"인지세" | 계약보증금 계산기 (인지세 포함) | title 에 "인지세" 없음, keywords 없음 |
| "수도광열비" | 예산 과목 분류 도우미 | keywords 에 **있는데도** 6질의 중 1건만 매칭 — 토큰 AND 가 다른 토큰에서 깨짐 |
| "집행률" | 예산 집행률 계산기 | 토픽이 0건이라 검색 자체가 도구로 못 감 |
| "명예퇴직수당" | 퇴직금 계산기 (keywords "명퇴") | "명예퇴직수당" 완전일치가 없음 |
| "연말정산" | 4대보험 정산보험료 계산기 | desc 에 "연말정산" 있음 — 토픽 부재로 순위 밀림 |
| "설계변경" | 설계변경 검토서 도우미 | COVERED 로 잡힘 (정상) |

**조치 성격 = `tools_registry` 의 `keywords` 필드 보강 (데이터 1줄씩).**
`tools_registry` 는 `app/helpers/tools_helper.rb` 에 있고 **P1.6 동결 목록에 없다.**
검색 recall 경로(`search_query_parser` · `topic.rb`)는 건드리지 않는다 → 654-query 지문 재측정 불필요.

> 이 트랙이 **가장 싸고 가장 즉효**다. 새 도구 0개, 새 글 0개, 코드 경로 변경 0.
> 다만 §5 "동의어 대량 자동 생성 금지"에 걸리지 않도록 **도구 keywords 만** 손대고
> `SYNONYMS` 사전은 건드리지 않는다. 이 둘은 다른 자리다.

### 3.1 WIZARD_CANDIDATE = NO 인 것과 그 이유

| 테마 | WIZARD | 이유 |
|---|---|---|
| 기간제·임기제 인사 | **NO** | 기관·직종별 지침 편차가 커서 **하나의 결정 트리로 수렴하지 않는다.** 잘못된 확신을 준다 |
| 연말정산·4대보험 | **NO** | 이미 계산기가 있다. Wizard 를 얹으면 중복 |
| 보조금 정산 | **NO** | 체크리스트 도구가 이미 그 역할 |
| 초과근무·수당 | **NO** | 조회(LOOKUP) 문제지 분기 문제가 아니다 |
| 명예퇴직·퇴직수당 | **NO** | 계산기 2종 보유 |
| 인지세 | **NO** | 단일 표 조회 |
| PQ·적격심사 | **NO** | 용어 문제 |

**"Wizard 로 만들 수 있다"와 "Wizard 여야 한다"를 구분했다.** 조회로 끝나는 것에 분기 트리를 얹는 것은
§2(단순함 우선) 위반이고, 편차가 큰 것에 확신 있는 트리를 얹는 것은 §20(근거 없는 생성) 위반이다.
