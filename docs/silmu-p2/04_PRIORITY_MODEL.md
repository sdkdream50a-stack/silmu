## 1. 왜 질의가 아니라 테마인가

211개 질의를 그대로 우선순위에 태우면 같은 업무가 여러 줄로 흩어져 빈도가 쪼개진다
("수의계약 한도"·"수의계약한도"·"소액수의"·"4천만원 수의계약"은 한 업무다).
그래서 **질의 → 테마 클러스터링**을 먼저 했다. 클러스터 정의는 `_measure/`(themes 매핑)에 남아 있고,
클러스터에 못 들어간 질의(예: "중고 책 사는데 유의사항이 따로 있어?")는 **버린 게 아니라 우선순위 밖**이다.

### 2.1 가중치를 두지 않은 이유

축별 가중치는 그 자체가 판단이고, 지금은 그 판단을 검증할 성과 데이터가 없다
(발행 후 CTR·해결률이 아직 없다 — 11 문서). 가중치를 지금 정하면 **근거 없는 정밀도**가 된다.
단순합으로 두고, 11 문서의 계측이 붙은 뒤에 재조정한다. 이건 §13 "추정치를 사실처럼 저장하지 않는다"의 적용이다.

### 2.2 이 모델이 못 보는 것 (명시)

```
G 축은 "근거가 존재하는가"이지 "우리가 확인했는가"가 아니다 — 09 문서가 별도로 본다
J 축은 판단이다. laws.effective_date 가 0/15 이라 실측 근거가 없다(01 §6)
A·C·D·F 는 사용자 인터뷰·설문이 아니라 도메인 판단이다 — 반증되면 바꾼다
빈도(E)는 5~9월 로그 3.5개월치다. 연말정산·결산처럼 계절성이 있는 업무는 과소평가될 수 있다
```

## 5. TIER 임계값 — 분포를 본 뒤에 정했다

§14 요구대로 처음부터 임의 컷오프를 만들지 않았다. 35개 실제 분포는 이렇다.

```
n=35   min=17   max=27   mean=21.8   median=21   Q75=24   Q90=26
```

| TIER | 임계 | 근거 | 건수 |
|---|---|---|---:|
| **P0** | SCORE ≥ 26 | 분포 Q90 | **4** |
| **P1** | 23 ≤ SCORE ≤ 25 | Q75 이상 | **12** |
| **P2** | 20 ≤ SCORE ≤ 22 | 중앙값 근처 | **11** |
| **BACKLOG** | SCORE ≤ 19 | 하위 4분위 | **8** |

**최저 17점도 "가치 없음"이 아니다.** 30점 만점 중 17점이며, 예컨대 `기록물 관리`(17)는
E=0(질의 없음)·B=0(감사사례 없음) 때문에 낮은 것이지 업무가 사소해서가 아니다.
E=0 은 "수요가 없다"가 아니라 **"우리 사이트에서 그 질문이 나온 적이 없다"**이고,
콘텐츠가 없으니 검색되지도 않는 순환이 섞여 있다 — 이 편향은 05 §4 에서 별도로 다룬다.

## 6. 다음 단계의 판정 순서

```
SCORE          → 후보 순서
GAP_TYPE       → 무엇을 만들 것인가 (글 / 바로답 / 절차 / 도구)
Asset Router   → 어떤 형태로 만들 것인가 (06·07)
Authority      → 근거를 댈 수 있는가 (09)   ← 여기서 막히면 순서를 내린다
```

**근거를 못 대는 항목은 점수가 높아도 먼저 만들지 않는다.** §18·§20 이 그 이유다.
