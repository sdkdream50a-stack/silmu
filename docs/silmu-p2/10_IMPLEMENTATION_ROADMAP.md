## 0. 이 로드맵의 전제

이번 감사가 뒤집은 전제 하나를 먼저 적는다.

```
착수 전 가정   "P2 = 일반행정 콘텐츠를 넓힌다"
실측 후 판정   콘텐츠 수(474건)는 이미 두껍다. 무너진 건 **DO 층과 발견성**이다
              · HowTo 보유 토픽      10 / 114   (8.8%)
              · Topic 근거 링크        0 / 114   (0%)
              · 211 실질의 중 3층 완비  20 / 211   (9.5%)
              · 도구 39개 중 상위질의에 매칭 실패  상위 20 중 8건
```

**따라서 P2 의 1순위는 "새 글"이 아니라 "이미 있는 자산을 답까지 연결하는 것"이다.**
이건 §12(검색 기회 ≠ 콘텐츠 생성)와 P2_HANDOFF §5(개수를 성과로 쓰지 않는다)의 직접 적용이다.

## 1. 선행 정정 — 콘텐츠 작업보다 먼저 (P-track)

새 자산을 만들기 전에 **지금 틀린 것**을 고친다. 셋 다 데이터 정정이고 P1.6 동결 코드 무관.

| # | 항목 | 근거 | 성격 | 크기 |
|---:|---|---|---|---|
| **P-1** | `bid-announcement`·`bidding` FAQ jsonb 정정 | 01 §7.1 — 공개 토픽 2건 · FAQ 9건이 파싱 실패로 소실 | 데이터 2행 | 매우 작음 |
| **P-2** | `provenance_confidence` HIGH↔UNVERIFIED 61건 정합 | 09 §7 — 미검증이 "확신 HIGH" | 데이터 61행 + 판정 규칙 | 작음 |
| **P-3** | `bid-notice-requirements` 의 `category="입찰"` 고아 정정 | 02 §2.2 · P2_HANDOFF §4 | 데이터 1행 | 매우 작음 |

**P-1 은 회귀 방지가 함께 가야 한다** — 지금은 `faq_list` 가 예외를 삼키고 `[]` 를 돌려주므로
같은 일이 또 생겨도 조용하다. 파싱 실패 건수를 **0 으로 고정하는 검사**가 있어야
"고쳤다"가 증명된다(양성대조: 일부러 깨진 값을 넣으면 검사가 잡아야 한다).

## 2. 추천 구현 TOP 5 (§28 — Quick Win / Moat / High-value / Newcomer / Tool 균형)

### R1 — 도구 발견성 복구 `[Quick Win]`
```
무엇     tools_registry 의 keywords 보강 (도구 8~12개)
왜       상위 20 중 8건이 "답을 가진 도구가 이미 있는데 질의에 안 잡힌다"(05 §4.3 · 07 §1)
범위     app/helpers/tools_helper.rb 의 keywords 필드만. 검색 recall 경로 무수정
크기     매우 작음 (데이터성 문자열 추가)
동결     ✅ 안전 — 654-query 지문 재측정 불필요 (SYNONYMS·parser·topic.rb 무관)
검증     · 회귀: "수의계약 한도"·"분할발주"·"인지세"·"수도광열비"·"명예퇴직수당"에서 tool_count ≥ 1
         · 음성대조: 무관 질의("병가")에 계약 도구가 새로 붙지 않을 것  ← 이게 없으면 keyword stuffing 이다
         · 기존 39 도구 검색 결과 스냅샷 before/after 대조
```

### R2 — 수의계약 한도 · 분할발주 Solution 완성 `[Moat]`
```
무엇     ① private-contract-limit 에 표제 FAQ("한도 금액이 얼마인가") 추가
         ② split-contract-prohibition 에 표제 FAQ + howto_steps
         ③ 두 토픽 → 계약방식 결정 도우미 / 분할계약 체크리스트 연결
왜       관측 1·2위 계약 질의군(37+25회)이 NO_DIRECT_ANSWER. 답이 코드 안에만 있다
크기     중간 (FAQ 4~6개 · howto_steps 2세트 · 연결)
근거     LOADED — 지방계약법 시행령·시행규칙 적재 완료
검증     · answer_for("수의계약 한도") 가 표제 FAQ 를 반환
         · **음성대조**: "숙박비 지급 기준"·"차비"에 이 FAQ 가 승격되지 않을 것 (P1.6 정밀도 회귀)
         · 654-query 지문 불변
```

### R3 — DO 층 파일럿: howto_steps 10 → 25 `[High-value]`
```
무엇     06 §3 의 PROMOTE 6건 + 검사검수·휴가 계열에 howto_steps 입력
왜       DO 층이 8.8% 다. Solution Page 골격은 있는데 안이 비어 있다(06 §1)
크기     중간~큼 (토픽당 4~6 step · 15 토픽)
근거     전건 LOADED (계약·회계·복무)
검증     · 각 step 이 법령 조문 또는 기존 Guide 문장에 추적 가능할 것 — **생성 금지**
         · 렌더 확인: topics#show L289 가 5 step 까지 표시
         · 양성대조: step 이 없는 토픽은 그 섹션이 안 뜨는지 (빈 껍데기 방지)
```

### R4 — 신규자 트랙 3종 증설 `[Newcomer]`
```
무엇     /start 에 예산집행 · 출장정산 · 급여복무 트랙 추가 (ONBOARDING_TRACK 확장)
왜       재료가 이미 있다 — 시리즈 80편 중 계약 30편만 소비 중(08 §3)
         홈 카드가 이미 "계약·예산·지출·급여"를 약속하고 있다(08 §2.1)
크기     작음~중간 (신규 저작 0 · 기존 Guide/AuditCase 재배열)
동결     ⚠️ home/index·_nav_v2 는 동결 목록 — **건드리지 않는다.** guides_controller 상수만
검증     · filter_map 이 미발행을 떨어뜨리는지 (빈 트랙 금지)
         · 각 트랙 렌더 개수 실측 (08 §7 에서 쓴 방법 그대로)
```

### R5 — 일상경비·예산과목 신규 토픽 2건 `[Tool 연계 + 순수 공백]`
```
무엇     Topic 신규 2건: 일상경비 지출증빙 · 세출예산 과목 분류
왜       관측 3위(36회)·5위(22회)인데 **Topic 0건**. 도구는 있는데 표제 콘텐츠가 없어 도달 불가
크기     중간 (신규 저작 2편 + FAQ)
근거     ⚠️ EXISTS_NOT_LOADED — 세출예산 집행기준 미적재
전제     **09 의 문서 적재가 선행**이거나, 근거를 댈 수 있는 범위로 축소해서 쓴다
검증     · 근거 없는 문장 0 — 조문·지침 인용 없는 단정 금지(§20)
         · 발행 후 "수도광열비"·"일상경비" 질의에서 tool_count ≥ 1 이 되는지
```

| `SYNONYMS` 확장 | P1.6 실측: 연상어 유입 → 상위범주 FAQ 오승격. R1 은 **도구 keywords** 로 우회 |

| 업무 카드 신설 | 카드는 콘텐츠의 결과. `MIN_COVERAGE` 가 자동으로 켠다 |

## 4. 탐색 트랙 (별도 · 승인 시)

04 §5 · 05 §4.1 의 편향 때문에 SCORE 로는 하위인데 **구조적으로 중요한** 4개.

```
정보공개 · 개인정보 · 기록물 · 행정절차
  E축(질의 수)이 낮은 이유 = 콘텐츠가 없어 검색될 수 없었던 순환
  C축(법적 영향) 3점 · 근거 EXISTS_NOT_LOADED
  → 09 문서 적재 후 재평가. 지금 순위로 버리지 않는다
```

§23 의 공공서비스(혜택) API · 정부24 혜택알리미는 **민원·정책 안내 영역에 fit 이 있다면**
이 탐색 트랙에 붙는다. 다만 민원 자산이 Guide 1건뿐이라(02 §2) **지금은 붙일 자리가 없다.**
보존만 하고 이번 P2 범위에 넣지 않는다.
