## 2. 분할발주 — `topics/split-contract-prohibition` · `topics/split-contract`

### 첫 화면 (§16)

문안이 조문과 일치하는지 확인한 결과 — **일치한다**:

- "나눠 계약했다고 모두 문제는 아니다" ← §77①1~3호 예외가 실재한다 ✅
- "한도·경쟁 회피 목적이면 위험할 수 있다" ← §77③ ✅

단, **물품·용역에는 위 두 문장을 그대로 쓰면 안 된다.** 그쪽은 금지가 아니라 §7제2호 합산이므로
"나눠 사도 추정가격은 12개월 총액으로 본다"가 정확한 문장이다. 도구에는 이미 반영했다.

### 구성

| 절 | 원천 | 상태 |

| 합리적 분리 사유 | §77①1~3호 | ✅ 도구 |
| 위험 신호 | §77③ | ✅ 도구 |
| 감사 관점 | AuditCase | ✅ |

## 3. 사용자 여정 (§14) — 구현된 연결

```
검색 "수의계약 한도"
  → Topic private-contract-limit (Tool 카드: 계약방식 결정 도우미)      [R1 에서 확보]
  → /tools/contract-method
      기관 선택 → 유형 → 금액 → 상대방
      → 판정 + 근거 조문 + 미해결 요인 + 다음 할 일
      → [혹시 한도를 피하려고 나눈 계약인가요?]  ← R2 신규 handoff
  → /tools/split-contract-checker
      트랙 자동 분기(공사 §77 / 물품·용역 §7제2호)
      → 판정 + 근거 + 적법 분리 사유 + 의무
      → [합산한 금액으로 계약방식 다시 확인하기]  ← R2 신규 역방향 handoff
  → 감사사례 검색 · 법령 원문(law.go.kr)
```

두 도구를 하나로 합치지 않았다(§14). 기능은 독립이고 **contextual handoff** 만 만들었다.
회귀 = `contract_decision_flow_test.rb` "계약방식 도구가 분할발주 도구로, 분할발주 도구가 계약방식 도구로 연결된다".

**3클릭 도달 측정**: 검색 → Topic → Tool = 2클릭, Tool → 다른 Tool = 3클릭, 근거 조문은
판정 화면 안에 직접 링크되어 **0추가 클릭**. §23 기준 충족.

## 4. Newcomer 연결점만 확인 (§24)

R4 는 구현하지 않았다. `/start` 트랙에서 계약방식 도구로 들어오는 인터페이스는
기존 `tool_next_actions` 파셜과 tools_registry 항목이 이미 제공한다 — 추가 작업 없이 연결 가능.
"처음 계약을 맡았어요" 질의는 현재 Topic 4건 · Tool 0건이며, 이는 R4 의 대상이지 R2 가 아니다.
