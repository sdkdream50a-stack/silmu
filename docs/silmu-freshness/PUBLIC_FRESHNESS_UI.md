# PUBLIC_FRESHNESS_UI — 공개 신선도 표시

## 1. 8상태 (§11)

| 상태 | 사용자 표시 | 성격 |
|---|---|---|
| `CURRENT` | 현재 기준 확인 | 정상 |
| `REVIEW_DUE` | 재검증 예정일 경과 | 주의 |
| `CHANGE_DETECTED` | 최신 개정사항 확인 중 | **알림** |
| `REVIEW_REQUIRED` | 최신 개정사항 검토 중 | **알림** |
| `VERIFIED_AFTER_CHANGE` | 개정 반영 확인 완료 | 정상 |
| `STALE_SUSPECTED` | 재검증 필요 | 주의 |
| `SOURCE_UNAVAILABLE` | 공식 출처 확인 불가 | **알림** |
| `UNKNOWN` | 확인 주기 미설정 | — |

boolean 하나로 표현하지 않는다.

## 2. 우선순위

```ruby
freshness_status
  = freshness_state (엔진이 관측한 값)   # 있으면 우선
  | derived_freshness_status             # 없으면 P1 의 재검증 기한 기반 유도값
```
엔진이 아직 보지 않은 콘텐츠도 안전하게 동작한다.

## 3. 표시 (§30·§31)

### 정상
```
✅ 공식 원문 확인 · 2026-06-15
   공식 발행 문서 원문까지 확인했습니다.  [검증 절차]
   📚 출처: 경기도교육청 감사관실 · 감사사례집 · 2021 p.122  [공식 원문 보기]
```

### 개정 검토 중 — **숨기지 않는다**
```
⚠ 최신 개정사항 검토 중
   근거 법령의 개정이 감지되어 이 콘텐츠에 미치는 영향을 검토하고 있습니다.
   검토가 끝나기 전까지는 공식 원문을 함께 확인해 주세요.
   감지된 개정 시행일: 2026.11.01 (시행 예정)
```

### 출처 확인 불가
```
⚠ 공식 출처 확인 불가
   공식 출처를 일시적으로 확인할 수 없습니다.
   중요한 업무 판단 전에는 공식 원문을 직접 확인해 주세요.
```

구현: `app/views/shared/_freshness_notice.html.erb`
노출 조건: `freshness_attention?` = `CHANGE_DETECTED | REVIEW_REQUIRED | SOURCE_UNAVAILABLE`
배치: 감사사례·토픽 show 의 본문 상단(검증 배지 위)

실측 확인:
- 영향받는 콘텐츠 → 알림 표시 + 시행일 노출 ✅
- 영향 없는 콘텐츠 → 알림 없음 (과잉 경고 안 함) ✅

## 4. 과장 금지 (§39)

다음 표현은 증명 전까지 쓰지 않는다.
```
항상 최신 / 100% 최신 / 자동으로 모두 반영 / 실시간 현행화 / 완전 자동 검증
```
전 페이지 실측 결과 이런 문구 **0건**.

## 5. 푸터 정정 (§38)

**변경 전** (사실과 달랐다 — 자동 검증 cron 은 2026-04-13 이후 꺼져 있었다)
> 실무.kr은 본 콘텐츠의 정확성을 높이기 위해 법제처 OPEN API 기반 **자동 검증 및 5단계 게이트를 운영하고 있으나**, …

**변경 후**
> 실무.kr은 법령·지침의 현행성을 지속적으로 점검하고 있습니다. 중요한 업무 판단 전에는 각 페이지의 기준일과 공식 근거를 함께 확인해 주세요. 법령 개정·해석 변경·개별 사안의 특수성으로 인한 오차가 있을 수 있으며, 본 콘텐츠에 전적으로 의존한 결과로 발생한 손해에 대해 실무.kr은 책임을 지지 않습니다.

**운영 검증 이후에 쓸 수 있는 표현** (§38 후단)
> 법령·지침 변경을 자동 감지하고, 영향받는 콘텐츠를 재검토하고 있습니다.

승격 조건은 `P2_GATE.md` 에 정의.

## 6. AI 답변 안전 게이트 (§33) — 인터페이스만

```ruby
STRONG_EVIDENCE_STATES = %w[CURRENT VERIFIED_AFTER_CHANGE]
WEAK_EVIDENCE_STATES   = %w[REVIEW_REQUIRED CHANGE_DETECTED STALE_SUSPECTED SOURCE_UNAVAILABLE UNKNOWN]
```
`AuthorityMetadata#freshness_status` 가 이 판정의 단일 입력이다.
AI 가 근거를 고를 때 `WEAK_EVIDENCE_STATES` 자료는 확정적 답변의 단독 근거로 쓰지 않는다.
**이번 단계에서는 상태 제공까지만 구현했다** — AI 연동은 P2(P1 의 grounding 배선과 함께).
