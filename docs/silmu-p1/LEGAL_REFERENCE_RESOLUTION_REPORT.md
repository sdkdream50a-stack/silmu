## 2. URL 규약 — 새로 발명하지 않았다

기존 운영 코드(`SeoHelper#legislation_ref`)가 쓰는 형식을 그대로 재사용한다.
```ruby
"https://www.law.go.kr/법령/#{canonical_name.delete(' ')}"
```

## 3. 해석 규칙과 confidence

| 상황 | 예 | confidence | 링크 |
|---|---|---|:--:|
| 허용목록 법령 | `지방계약법 시행령 제25조` | HIGH | ✅ |
| 약칭 → 정식명 | `국가계약법` → `국가를 당사자로 하는 계약에 관한 법률` | HIGH | ✅ |
| 하위법령 상속 (상위법 1개일 때) | `지방계약법 제30조, 시행령 제90조` | HIGH | ✅ |
| 하위법령 상속 (상위법 2개 이상) | — | MEDIUM | ❌ |
| 대용어 해석 불가 | `같은법 시행령 제5조` (앞에 법 없음) | LOW | ❌ |
| 허용목록 밖 | `경기도 공립학교회계 규칙` | LOW | ❌ |

허용목록 `KNOWN_LAWS` 는 **51개 항목**이며, 국가법령정보센터에 "법령"으로 존재하고 이름만으로 유일하게 식별되는 것만 넣었다.

### 실제 데이터의 함정 3가지 (전부 처리함)
1. **대용어** — `같은법 시행령`(34) `같은 법 시행령`(11) `시행령`(11) `시행규칙`(3) 등 45건 이상. 직전 상위 법령을 상속하되 **문자열 안에 상위법이 정확히 하나일 때만** HIGH.
2. **괄호 안 쉼표** — `관리요령(재무기획관-40945, 2020.12.31.)` 을 쉼표로 자르면 `2020.12.31.)` 이 법령명이 된다. 괄호 깊이를 세어 분리하지 않는다.
3. **자치법규·내부지침** — 30건 이상 존재. 링크하면 전부 오링크가 된다.

## 4. 생성 URL 전수 검증 (§17·§36)

### 음성 대조 — HTTP 200 은 증거가 아니다
```
GET https://www.law.go.kr/법령/존재하지않는가짜법률명칭  → HTTP 200
  <title>국가법령정보센터 | 오류페이지</title>
```
**law.go.kr 은 존재하지 않는 법령명에도 200 을 반환한다.** 상태 코드로는 검증할 수 없고 `<title>` 로 구분해야 한다.

### 양성 대조 — 실제 데이터에서 생성되는 URL 전수
```
해석기가 dev 데이터에서 생성하는 distinct URL: 41개
검증 결과: OK 41 / INVALID 0
```
41개 전부 `<title>` 이 법령명으로 나왔다(오류페이지 0). 즉 **해석기가 만들 수 있는 링크는 전부 실제 법령에 도달한다.**

> 이 검증이 없었다면 "링크를 만들었다"는 주장은 근거가 없었을 것이다. HTTP 200 만 봤다면 가짜 법령명도 통과했을 것이다.

## 6. 도구에도 동일 적용

`config/tool_trust.yml` 의 `laws:` 문자열이 같은 해석기를 거쳐 링크로 승격된다.
예: `/tools/contract-method` → `지방자치단체를 당사자로 하는 계약에 관한 법률 제9조`, `… 시행령 제25조, 제30조` (둘 다 링크)
