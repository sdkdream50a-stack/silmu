# NEW_INFORMATION_ARCHITECTURE — 신 정보구조 설계

> 현재 IA는 **콘텐츠 종류 중심**(topics / guides / audit-cases / tools / templates)이다.
> 사용자는 "가이드를 읽고 싶다"고 오지 않는다. **"이 업무를 끝내야 한다"**고 온다.
> 신 IA는 **업무(Task) × 기관(Agency) × 근거(Evidence)** 3축을 동시에 성립시킨다.

## 3. 3축 모델

```
                    ┌──────────────┐
                    │   QUESTION   │  "병가 며칠부터 진단서?"
                    └──────┬───────┘
                           │ canonicalize
                    ┌──────▼───────┐
        ┌──────────►│     TASK     │◄──────────┐
        │           │ 02.병가.증빙  │           │
        │           └──────┬───────┘           │
   ┌────┴─────┐            │             ┌─────┴──────┐
   │  AGENCY  │            │             │  EVIDENCE  │
   │ 교육청/지자체│◄──────────┴────────────►│ 법·령·규칙·예규│
   └──────────┘   어느 기관에 어떤 근거가      └────────────┘
                      적용되는가
```

- **TASK**가 URL의 1급 시민이 된다. 콘텐츠 종류(topic/guide/case)는 TASK에 붙는 *뷰*다.
- **AGENCY**는 필터가 아니라 **답을 바꾸는 차원**이다 (`AGENCY_RULE_MODEL.md`).
- **EVIDENCE**는 모든 주장에 연결된 그래프 노드다 (`SOURCE_GRAPH_DESIGN.md`).

## 4. URL 설계 (기존 URL 100% 보존)

### 4.1 신규 (추가)
```
/work                              오늘 어떤 업무 때문에 막히셨나요 (신규 진입점)
/work/:domain                      예: /work/duty   (02 복무)
/work/:domain/:task                예: /work/duty/sick-leave   ← Solution Page
/agency/:agency_type               기관별 진입 (education-office, local-government, …)
/evidence/law/:law_slug            근거 중심 진입 (법령 → 이 법이 지배하는 업무들)
```

### 4.2 기존 (전부 유지 · 301 없음)
`/topics/:slug` `/guides/:slug` `/audit-cases/:slug` `/tools/:slug` `/templates/:id` `/series/:slug`

> **기존 URL을 옮기지 않는다.** 신 IA는 기존 페이지 위에 **얹는 레이어**다. 색인 자산 564 URL을 위험에 빠뜨리지 않는다.
> `topics.task_key` 컬럼 하나만 추가하면 기존 토픽이 그대로 TASK 뷰에 나타난다.

### 4.3 통합이 필요한 경우
`slug_redirects` 테이블(이미 존재, 현재 0행)로 301을 데이터 관리한다. `MERGE` 6건이 첫 대상.

## 5. 홈 IA (`UX_HOMEPAGE_IA`는 §17 요구를 여기에 통합)

기존: 콘텐츠 종류를 앞세운 네비게이션.
신규 진입 문장:

> ### 오늘 어떤 업무 때문에 막히셨나요?

**대표 CTA 8** (도메인 매핑)
| CTA | → 도메인 | 현재 보유 콘텐츠 |
|---|---|---:|
| 계약해야 해요 | 05 | 193 ✅ |
| 예산을 집행해야 해요 | 04 | 107 ✅ |
| 복무가 궁금해요 | 02 | 73 ✅ |
| 급여·수당이 궁금해요 | 03 | 45 ✅ |
| 민원 답변해야 해요 | 08 | **0** ⚠️ |
| 정보공개 청구가 왔어요 | 09 | **2** ⚠️ |
| 감사를 준비해야 해요 | 11 | 4 (+감사사례 257) |
| 새 업무를 맡았어요 | onboarding | `/start` 기존 |

> ⚠️ **CTA를 먼저 만들면 빈 방으로 안내하게 된다.** 민원·정보공개 CTA는 해당 도메인 콘텐츠가 최소 임계(권장 5건 이상)를 넘긴 뒤 노출한다. P0 감사 완료 전 P3 확장 금지 원칙(§20)과 일치.

**"처음 맡은 업무인가요?"** 보조 진입: 신규공무원 · 첫 계약 · 첫 예산 · 첫 감사 · 첫 민원 · 첫 결산.

## 6. 마이그레이션 순서 (안전 순)

1. `task_key` `domain` 컬럼 추가 (nullable) → 기존 549건 backfill (`proposed_domain` 컬럼이 이미 CSV에 있음)
2. `99_미분류 95건` 수동 판정 → 도메인 확정
3. `/work` 계층을 **읽기 전용 뷰**로 신설 (기존 페이지 재사용, 콘텐츠 복제 0)
4. 홈 CTA는 도메인 임계 충족분만 노출
5. 빈 도메인(01·08·12·14·15)은 P3에서 채운다 — **P0 종료 전 착수 금지**
