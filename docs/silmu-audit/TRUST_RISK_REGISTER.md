## TR-01 — 사용자에게 git 커밋 해시가 "검토 출처"로 표시된다 · P0 CRITICAL

**근거 (실측).** 감사사례 257건 중 **119건(46%)**의 화면 상 `📚 검토 출처:` 값이 내부 엔지니어링 로그다.
(양성 대조: 같은 추출기가 토픽 페이지에서는 `1차 출처: 법제처 국가법령정보센터`를 정상 추출한다.)
```
출처: Phase A~E batch 01~03 (commits eed3ceb..12dff5d) — 법제처 OPEN API 5단계 게이트 검증
출처: 법제처 OPEN API mcp spot check + 부정확 정정 (lawId 001234·…, 2026-05-19 batch 02 — 폐지 조문 3건 + 잘못된 § 2건)
출처: sen_2025_audit_disclosure_dashboard
```
`<aside aria-label="콘텐츠 검증 정보">` 안 `<cite class="legal-cite">`로 렌더된다 — 즉 **인용(citation)으로 마크업된 채** 노출된다.

**피해.** 감사 대비로 들어온 공무원이 근거를 확인하려 할 때 `commits eed3ceb..12dff5d`를 본다. 이는 근거가 없다는 사실보다 나쁘다 — *근거를 위장한다*. "카페보다 정확하다"는 북극성이 이 한 줄에서 무너진다.

**단서(양성 대조에서 확인).** 조문 자체는 대부분 적혀 있다 — 257건 중 **219건이 `제N조`/`§N` 표기를 보유**하고, 94건은 `law.go.kr 검증 근거: 지방계약법 시행령 제25조`처럼 **도메인을 텍스트로만** 쓴다(클릭 불가). 즉 링크로 바꿀 재료가 이미 본문에 있다.

**수정 성격.** 콘텐츠 재작성 불필요. `source`(사례 출처)와 `verification_method`(법령근거 검증 방법)를 **분리 렌더**하고, 검증 방법은 사용자 언어로 번역하거나 비공개 처리. 템플릿 1곳 + 데이터 마이그레이션.

## TR-02 — 재구성 사례에 "5단계 정합성 검증 완료" 배지가 붙는다 · P0 CRITICAL

**근거.** 배지 보유 246건 중 **110건이 본문에서 스스로 "특정 실사례 아님"**을 밝힌 silmu 재구성 사례다.

> **정정 (2026-09-05 P1 세션).** 최초에 `사이트 어디에도 "5단계"의 정의가 없다` 고 적었으나 **틀렸다.**
> `app/views/home/about.html.erb:112-140` 에 5단계가 항목별로 정의되어 있다.
> 실제 결함은 두 가지다 — ① 배지에서 그 설명으로 **도달할 수 없었고**(링크 없음)
> ② about 의 정의 자체가 "모든 **법령 콘텐츠**는 발행 전 5단계 정합성 검증을 거치며" 즉 *법령* 검증인데,
> 그 배지가 재구성 감사사례 위에 놓여 *사례 사실관계* 검증으로 읽혔다.
> P1 에서 배지 문구를 검증 범위별로 분리하고 `/about` 링크를 추가해 해소했다.

**피해.** 배지는 *법령 근거*를 검증했다는 뜻인데, 위치와 문구 때문에 *이 사건이 실제로 있었다*로 읽힌다. 실제로 이 사례들의 본문은 `○○군청`, `△△도 K 사무관(5급)`, `47건·380만원` 같은 구체적 서술을 쓴다(익명 플레이스홀더 포함 200건). 사용자가 이를 실제 감사 지적으로 인용해 기안하면 사실관계 오류가 된다.

**수정 성격.** provenance 4분류(§AUDIT_CASE_PROVENANCE_SPEC) 라벨을 **제목 옆·상단에** 노출하고, 배지 문구를 `법령 근거 검증 완료`로 한정. 콘텐츠 본문 무수정.

## TR-03 — 금액·기한을 산출하는 도구 30개에 면책·한계 문구가 없다 · P0 HIGH

**근거.** 도구 37개 중 면책 문구 보유 **7개**, 기준 연도 표기 보유 **5개**, 검증 배지 **0개**.
기준일 없는 도구 32개에 `contract-guarantee`(계약보증금), `estimated-price`(예정가격), `legal-period`(법정기간), `severance-calculator`(퇴직금), `qualification-evaluation`(적격심사) 등 **금액·낙찰·기한을 직접 산출하는 도구가 전부 포함**된다.
도구의 기준값을 소유한 파일: `config/legal_standards.yml` `version: 2026-02-04`, `config/contract_thresholds.yml` 최종 `2026-03-28`.

**피해.** 사용자는 계산 결과를 그대로 기안에 옮긴다. 기준값이 7개월 전 스냅샷인데 화면은 그 사실을 말하지 않는다. 개정이 있었다면 **도구가 감사 지적을 생산한다.**

**수정 성격.** 공통 파셜 1개(`기준일 · 근거조문 · 재확인 안내`) + YAML의 `version`을 화면에 노출. 계산 로직 무변경.

## TR-09 — AI 근거 주입 기능이 있는데 UI에 배선되지 않았다 · P1 HIGH

**근거 (양성 대조 후 정정).** 최초에 "근거 주입 경로가 없다"고 적었으나, 전수 확인 결과 **주입 코드는 존재한다.**
`app/channels/ai_assistant_channel.rb:31-44`가 `topic_slug`가 오면 `Topic#law_content/decree_content/rule_content/commentary/practical_tips`를 이어붙여 `topic_context`로 주입한다.

문제는 그 경로가 **실제로 도달 불가능하다**는 것이다.
- `/ai-assistant` 뷰는 `data-ai-chat-topic-slug-value="<%= @topic&.slug.to_s %>"`이고, 컨트롤러는 `params[:topic_slug]`로만 `@topic`을 찾는다.
- **사이트 어디에도 `topic_slug`를 붙여 `/ai-assistant`로 보내는 링크가 없다.** `ai_assistant_path` 참조는 네비게이션 2곳뿐이며 둘 다 파라미터 없음. (양성 대조: 같은 grep이 `topics_path` 링크는 9건 찾는다 → 검출기 정상.)
- 토픽 페이지에 `ai-chat` 위젯 임베드도 없다.

그리고 **retrieval은 실제로 없다** — `embedding|pgvector|vector|faiss|semantic|similarity_search|retriev|knn|cosine|Qdrant|Pinecone|Weaviate|chroma|langchain|llama_index`로 확대 재검색해도 일치 0건(양성 대조: 같은 명령·경로로 `anthropic|haiku`는 74건 매칭).

**정확한 진단: 근거 주입 기능은 만들어졌으나 UI에 배선되지 않았고, 질문에서 올바른 토픽을 찾아주는 retrieval이 없어 사실상 모든 실사용 세션이 무근거다.**

**피해.** 북극성 ④ "일반 AI보다 근거가 확실하다"가 성립하지 않는다. 사이트는 법제처 딥링크 813개와 검증된 토픽 114건을 갖고 있는데 **AI는 그것을 쓰지 않는다.**

**수정 성격.** P1 최고 ROI 항목. **주입 코드가 이미 있으므로 ① 토픽 페이지에 위젯 임베드(또는 `topic_slug` 링크) ② 질문→토픽 retrieval** 두 가지만 하면 된다. `llms-full.txt`(563KB)가 이미 완성된 코퍼스이고, `pg_trgm`도 이미 설치되어 있다.
