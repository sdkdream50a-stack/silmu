# SOLUTION_PAGE_SPEC — 표준 실무 해결 페이지 규격

> 북극성 ⑤ "매뉴얼보다 실제 업무를 빨리 끝낼 수 있다"를 페이지 한 장으로 구현한다.
> 현재 토픽 페이지는 본문 중앙값 12,147자로 이미 길다. **더 쓰는 것이 아니라 순서를 바꾸는 일이다.**

---

## 1. 설계 원칙

1. **결론 먼저.** 사용자는 읽으러 온 게 아니라 끝내러 왔다.
2. **적용 대상을 결론보다 먼저 확정한다.** 기관이 다르면 결론이 다르다.
3. **모든 수치에 근거와 기준일이 붙는다.** 예외 없다(토픽은 이미 결손 0건 — 이 규율을 전 페이지로).
4. **재구성/해석과 공식 근거를 시각적으로 분리한다.**
5. **다음 행동으로 끝난다.** 도구·서식·기안문구로 연결되지 않으면 미완성이다.

---

## 2. 표준 12 블록

| # | 블록 | 필수 | 데이터 원천 | 현재 보유 |
|---|---|:--:|---|---|
| 1 | **바로 답** (3~5줄) | ✅ | `summary` | 토픽 일부 |
| 2 | **적용 대상** | ✅ | `target_agency` `jurisdiction` `fiscal_system` | **22%만** ⚠️ |
| 3 | **핵심 기준** (금액·기한·조건) | ✅ | `agency_rules` | YAML 2종 |
| 4 | **업무 처리 순서** STEP 1..N | ✅ | `howto_steps` (jsonb, 존재) | 토픽 10건 HowTo |
| 5 | **필요한 서류** 체크리스트 | ✅ | `templates` 연결 | 26 서식 |
| 6 | **시스템 처리** (어디서 무엇을) | | 신규 (도메인 15) | **없음** ⚠️ |
| 7 | **기안·결재 예시 문구** | | 신규 | 도구 일부 |
| 8 | **자주 틀리는 부분** | ✅ | `audit_cases` 연결 | 257건 |
| 9 | **관련 실제 사례** | | `audit_cases` + provenance 라벨 | 257건 |
| 10 | **관련 도구** | | `tools` | 37개 |
| 11 | **근거** (법·령·규칙·예규 + 원문 링크) | ✅ | `SOURCE_HIERARCHY` Tier 표기 | 토픽 100% ✅ |
| 12 | **변경이력** | ✅ | `content_migrations` + `review_due_at` | 원장 존재, 미노출 |

### 블록 6·7이 진짜 차별점이다
"어디서 무엇을"(온나라·e호조·나라장터·K-에듀파인)과 "그대로 쓸 수 있는 기안 문구"는
법제처에도 카페에도 없다. **북극성 ①③⑤를 동시에 만족시키는 유일한 블록이다.** 현재 0건이므로 P2의 최우선.

## 3. 렌더 순서와 화면 계약

```
┌──────────────────────────────────────────────┐
│ [내 기관: 시·도교육청 ▾]        기관 미선택 시 먼저 물음 │
├──────────────────────────────────────────────┤
│ ① 바로 답                                     │
│    물품 1인 견적 수의계약은 2,000만원 이하에서 가능합니다.│
│    2,000만원 초과 5,000만원 이하는 2인 이상 견적입니다.  │
├──────────────────────────────────────────────┤
│ ② 적용 대상   시·도교육청 · 교육지원청 · 공립학교        │
│              (중앙행정기관은 국가계약법 §26 — 다름 →)    │
├──────────────────────────────────────────────┤
│ ③ 핵심 기준   [표] 금액 · 기한 · 조건 + 각 행에 근거 조문 │
├──────────────────────────────────────────────┤
│ ④ 처리 순서   STEP 1 … STEP N   (각 STEP에 시스템·서식) │
│ ⑤ 서류 체크리스트                                │
│ ⑥ 시스템 처리   나라장터 → 계약요청 → …              │
│ ⑦ 기안 예시 문구   [복사]                          │
├──────────────────────────────────────────────┤
│ ⑧ 자주 틀리는 부분 (감사 위험)                      │
│ ⑨ 관련 사례   🏛 실제 / 📘 재구성  ← 라벨 강제         │
│ ⑩ 관련 도구                                     │
├──────────────────────────────────────────────┤
│ ⑪ 근거   [Tier 1] … 원문 → · 기준일                │
│ ⑫ 변경이력   2026-06-15 조문번호 정정 · 2026-05-20 …  │
└──────────────────────────────────────────────┘
```

**필수 규칙**
- ②가 확정되기 전에는 ①③을 확정 값으로 보여주지 않는다.
- ③의 모든 셀은 `agency_rules` 행을 참조한다 — 본문 하드코딩 금지(현재 상수 드리프트의 원인).
- ⑨는 `provenance` 라벨 없이 렌더 불가.
- ⑫는 `content_migrations` 원장에서 자동 생성 — 사람이 쓰지 않는다.

## 4. 기존 토픽에서의 이행

현재 토픽은 `법률 / 시행령 / 시행규칙 / 해석` 4카드 구조 + FAQ + 감사사례 연결이다.
**본문을 다시 쓰지 않는다.** 다음만 한다:

| 작업 | 방법 | 위험 |
|---|---|---|
| ② 적용 대상 블록 신설 | `target_agency` backfill 후 파셜 추가 | 낮음 |
| ③ 핵심 기준을 `agency_rules` 참조로 전환 | 단계적 (계약 도메인부터) | 중간 |
| ⑨ 사례에 provenance 라벨 | `AUDIT_CASE_PROVENANCE_SPEC` backfill 후 | 낮음 |
| ⑪ Tier 표기 추가 | 기존 링크에 등급 라벨만 | 낮음 |
| ⑫ 변경이력 노출 | `content_migrations` 조회 뷰 | 낮음 |
| ⑥⑦ 신규 작성 | 도메인별 순차 | — (P2) |

기존 `sections` / `howto_steps` / `faqs` / `quick_stats` jsonb 컬럼이 이미 있으므로 **스키마 추가 없이 블록 대부분을 채울 수 있다.**
