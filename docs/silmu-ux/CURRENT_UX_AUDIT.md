## 3. 홈페이지 현황 (`home/index.html.erb`, 409줄)

```
1. HERO           — 헤드라인 + 검색 + 인기검색어 칩 8 + sector 탭
2. 업무달력 strip
3. 최근 본 항목    (localStorage, 기본 숨김 — 이미 존재)
4. 핵심 실무 도구  (3 major + minor)
5. (섹션) 큐레이션 토픽 / 감사사례 / 인기 가이드
6. CTA
```

평가:
- ✅ 검색이 이미 hero 에 있다 (§17 의 절반은 이미 충족)
- ✅ `최근 본 항목` 이 이미 localStorage 기반으로 존재 (§43 — 새로 만들 필요 없음)
- ❌ placeholder 가 `"예: 수의계약 한도, 출장비 정산, 보조금, 연말정산"` — **키워드 유도**다.
  §17 이 요구하는 "무엇을 처리하려고 하세요?" 라는 **질문 유도**가 아니다.
- ❌ 업무 진입점(Task Entry) 이 없다. 도구·토픽·사례를 종류별로 전시한다 (§15 위반).
- ❌ lede 가 콘텐츠 개수를 자랑한다 (`가이드 195개, 사례 191건`) — §83 금지 항목.

## 4. 검색 현황 (`ChatbotController#search`) — **가장 심각한 결함**

### 구조
`/silmu-search` → 5개 소스를 각각 조회 → **콘텐츠 종류별로 나열**
```
실무 도구 (n) / 법령 가이드 (n) / 감사사례 (n) / 실무 가이드 (n) / 서식 (n)
```
→ §20 이 지목한 바로 그 구조. **"바로 답"이 없다.** 사용자가 답을 찾으려면 글을 열어야 한다.

### 실측: 자연어 질문은 지금 **0건**을 반환한다

`Topic.search_multiple` 은 토큰을 **전부 AND** 매칭한다.
자연어 문장의 조사·어미·의문사가 어떤 필드에도 없으므로 AND 가 즉시 깨진다.

| 쿼리 (§17 예시 그대로) | 토큰화 결과 | 결과 |
|---|---|---:|
| `병가 며칠 쓰면 진단서 내야 하나요` | 병가/며칠/쓰면/진단서/내야/하나요 | **0** |
| `출장비 얼마 지급하나` | 출장비·여비/얼마/지급하나 | **0** |
| `정보공개 답변은 며칠 안에 해야 하나요` | 정보공개/답변은/며칠/안에/해야/하나요 | **0** |
| `처음 계약을 맡았어요` | 처음/계약을/맡았어요 | **0** |
| `3000만원 물품 수의계약 가능한가요` | … | 11 (우연히 생존) |

같은 의도를 키워드로 줄이면 즉시 살아난다:
| 키워드형 | 결과 |
|---|---:|
| `병가 진단서` | 3 (sick-leave 정확 매칭) |
| `수의계약 한도` | 12 |
| `출장 차비` | 2 |
| `정보공개 처리기한` | **0 — 콘텐츠 자체가 없음** |

**진단**: 자연어 실패는 랭킹 문제가 아니라 **recall 이 구조적으로 0** 인 문제다.
`연가 돈으로`(§18 예시)도 `연가보상비` 동의어가 없어 토픽 0건이다.

**처방(§53 준수 — LLM 아님)**:
1. 조사·어미·의문사 **stopword 제거** (`하나요`,`며칠`,`얼마`,`인가요`,`되나요`,`해야`,`쓰면`…)
2. 전 토큰 AND 로 0건이면 **점진적 완화**(내용어 부분집합 매칭)로 재시도
3. §18·§54 의 고가치 동의어를 `SearchQueryParser::SYNONYMS` 에 소량 추가

### 이미 있어서 재사용할 것 (§42·§58 — 새로 만들지 않는다)
- `SearchLog`: `zero_result` · `clicked_at` · `clicked_result_type` · `clicked_result_rank` · `source`
- `SearchLog.content_gap_candidates` / `unsatisfied_queries` — **Question Radar 의 signal 기반이 이미 있다**
- `ChatbotController#click` — 클릭 계측 엔드포인트 존재
- `SearchQueryParser` — 토큰화 + 동의어 레이어 존재 (13쌍)

## 6. 설계 판정

1. **답은 이미 있다(FAQ 331건). 검색이 그걸 못 찾을 뿐이다.**
   → P1.6 의 최대 ROI 는 화면 장식이 아니라 **recall 복구 + answer surfacing**.
2. **빈 카테고리 판정은 하드코딩하지 않는다.**
   dev≠운영이므로 내가 센 0건을 코드에 박으면 운영에서 틀린다.
   → Task Entry 는 **런타임 count 기반**으로 노출/비노출을 결정한다.
3. **정보공개는 정직하게 없는 것으로 다룬다.**
   §56 task test D 는 "개선"이 아니라 **Zero Result UX 의 정직한 실증**으로 측정한다(§41·§42).
