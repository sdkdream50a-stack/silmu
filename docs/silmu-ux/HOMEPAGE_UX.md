# HOMEPAGE_UX — P1.6 Phase C

> §15~§17·§24·§43·§83. 홈은 콘텐츠 전시장이 아니라 **업무 진입점**이다.

## 1. BEFORE → AFTER

| | BEFORE | AFTER |
|---|---|---|
| 헤드라인 | "실무 가이드·도구·감사사례, 한 번에 검색" | **"공무원 업무, 찾는 데서 해결까지"** |
| Lede | "실무 가이드 195개, 감사 지적 사례 191건이 여기 있습니다" | "법령·절차·감사사례·계산도구를 한 번에 찾아보세요" |
| placeholder | "예: 수의계약 한도, 출장비 정산…" (키워드 유도) | **"무엇을 처리하려고 하세요?"** (질문 유도) |
| 검색 보조 | 인기 검색어 칩 8개(단어) | **예시 질문 4개(문장)** |
| 업무 진입 | 없음 | **업무 카드 8개** (런타임 count 게이트) |

§83 준수: 콘텐츠 개수 자랑 제거. 카드 남발 없음(8개). 아이콘은 카드당 1개.

## 2. 예시 질문 — 실제로 결과가 나오는 것만 건다

```
병가 며칠 쓰면 진단서 내야 하나요     → 바로 답 있음
3000만원 물품 수의계약 가능한가요      → 결과 6건
출장비 얼마 지급하나                → 바로 답 있음
처음 계약을 맡았어요                → 결과 6건
```
**정보공개는 넣지 않았다.** 전 자산 0건이라 첫 클릭이 곧바로 빈손이 된다.
회귀 테스트가 이 문장의 부재를 고정한다(`task_first_navigation_test`).

## 3. 업무 카드 (§24)

`TaskEntryHelper` — 노출 판정은 **런타임 count**(topic+guide+audit 합산, 임계 3).
dev 측정치를 코드에 박지 않는다. 운영(Topics 114) 과 dev(92) 가 다르기 때문이다.

현재 dev 노출: 계약·조달 219 · 예산·회계 120 · 감사·청렴 191 · 처음 맡은 업무 80 ·
복무 35 · 여비·출장 15 · 보수·수당 12 · 보조금 11
자동 제외: **재산·물품 0**. 정보공개·시설·안전은 매핑 자체가 없다(콘텐츠 0).

콘텐츠가 생기면 카드가 저절로 나타난다 — 회귀 테스트가 그 성질을 고정한다.

## 4. 순서 (§60)

```
HERO(검색 주인공) → 업무 카드 → 최근 본 항목(기존 localStorage) → 업무달력 →
핵심 도구 → 큐레이션/사례/가이드 → CTA
```
기존 섹션은 **하나도 삭제하지 않고** 아래로 재배치했다.

## 5. 하지 않은 것

새 personalization 시스템 · SNS · 챗봇 팝업 · dashboard 화 · 회원가입 강제 ·
`최근 본 항목` 재구현(이미 있던 localStorage 컨트롤러 그대로 씀).
