## 1. 모바일 첫 화면 (§45)

390×844 에서 스크롤 전에 다음이 전부 들어온다.
```
헤드라인(공무원 업무, 찾는 데서 해결까지) · 검색창("무엇을 처리하려고 하세요?")
· 예시 질문 4개 · 내 직종 탭
```
검색 결과 화면(390px)에서도 **바로 답 카드가 첫 화면**에 들어온다.

## 4. 접근성 (§48)

| 항목 | 결과 |
|---|---|
| h1 | 전 페이지 정확히 1개 |
| img alt 누락 | **0** |
| semantic heading | 신설 섹션 전부 `<h2 id>` + `aria-labelledby` |
| aria | 업무 카드 그룹·상태 칩 그룹에 `role`/`aria-label` 부여, 장식 아이콘 전부 `aria-hidden` |
| form label | 홈 검색 input `aria-label="처리하려는 업무 검색"` |
| 키보드/포커스 | 기존 `focus-visible:ring` 유틸 유지, 신설 요소는 표준 `<a>`/`<button>` |

### 미해결 (P1.6 범위 밖 · 선재 결함)
- 토픽 페이지의 `closeDocPopup()` 버튼이 SVG 만 있고 접근 이름이 없다 → **P1.6 이전부터 존재**.
  §3(외과적 변경)에 따라 이번에 고치지 않고 보고만 한다.
- 프로브가 `input[type=submit]` 2건을 "라벨 없음"으로 셌으나 **오탐**이다
  (submit 은 `value` 가 접근 이름). 검출기 쪽 한계를 그대로 기록한다.

## 5. Sticky action (§47)

**추가하지 않았다.** 기존 우하단 도구 FAB 가 이미 있고, 그 위에 또 얹으면
모바일 첫 화면 예산(§45)을 갉아먹는다. §47 은 "무조건 추가하지 않는다"고 했다.
