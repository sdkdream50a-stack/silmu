# TASK_TAXONOMY — P1.6 Phase B

> 업무(task) 분류의 정본. §24·§25 기준. 2026-09-06 dev 실측 기반.

---

## 1. 원칙

- taxonomy(콘텐츠 종류)는 **내부에 유지**한다. 사용자에게는 업무로 보인다(§12).
- **없는 업무를 만들지 않는다.** 커버리지 0 인 칸은 노출하지 않는다(§24).
- 커버리지 판정은 **런타임 count** 다. dev 측정치를 코드에 박지 않는다
  (운영 Topics 114 vs dev 92 — 내 측정은 부분집합이다).
- P1.6 은 **UI 기반만** 만든다. 콘텐츠를 대량 생성하지 않는다(§25).

→ §56 task test D 는 **Zero Result UX 의 실증 케이스**로 사용한다.

## 3. 신규자 진입점 (§26)

새로 만들지 않고 **기존 완전정복 시리즈 8종을 재사용**한다.

| 진입 문장 | 연결 대상 (기존 자산) |
|---|---|
| 처음 계약을 맡았어요 | 수의계약_완전정복 / 공사계약_완전정복 / 입찰_완전정복 |
| 처음 예산을 맡았어요 | 예산편성_완전정복 |
| 처음 지출을 맡았어요 | 예산집행_완전정복 |
| 처음 급여를 맡았어요 | 인사복무_완전정복 |
| 처음 출장 정산을 맡았어요 | 출장여비_완전정복 |
| 처음 보조금을 맡았어요 | 지방보조금_완전정복 |
| 처음 감사를 받아요 | 감사 빈출 지적 TOP 30 (`/guides/audit-frequent-issues`) |

**"처음 민원을 맡았어요" 는 만들지 않는다** — 대응 자산이 guide 1건뿐이다.

## 4. P2 확대 후보 (구현 안 함)

§25 의 15분류는 **P2 정본 후보**로만 기록한다.
P1.6 은 위 표의 매핑 구조만 만들고, 빈 칸은 P2 콘텐츠 확대 시 자동으로 채워진다
(런타임 count 게이트이므로 콘텐츠가 생기면 카드가 저절로 나타난다).
